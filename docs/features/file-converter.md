# Local app-owned file converter

Minecraft Server Studio provides a bounded, local-only desktop converter for a
small set of formats that the installed application implements itself. It is
not a general document, media, archive, workbook, or cloud conversion service.
The native desktop process owns every source and destination picker; the
renderer never supplies a filesystem path.

## Enabled conversion routes

The converter validates an eligible source completely before it offers a
target. It does not trust a filename extension or guess a malformed structured
document.

| Source after full bounded validation | Available output | Important boundary |
| --- | --- | --- |
| Printable UTF-8 text | UTF-8 text, Base64, hex | The UTF-8 output removes a byte-order mark and writes a new file; it does not change the source. |
| JSON | UTF-8 text, JSON, CSV, TSV, YAML-style text, Base64, hex | JSON must parse and stay within the documented value/depth bounds. |
| CSV or TSV | UTF-8 text, JSON, CSV, TSV, YAML-style text, Base64, hex | Delimited text must have a bounded valid header/row shape. Quoting is validated before a table is offered. |
| Limited YAML-style data | UTF-8 text, JSON, CSV, TSV, YAML-style text, Base64, hex | This is the restricted grammar below, not a general YAML parser. |
| Any other bounded local bytes, including recognized unavailable formats | Base64, hex | Encoding does not claim to decode, render, or semantically convert the native format. |

CSV and TSV output from JSON/YAML-style data is available only for a top-level
array of record objects with scalar values. Nested values are refused rather
than silently flattened or dropped. JSON output retains the validated value;
formatting can change, but the converter does not intentionally omit fields.

## YAML-style subset

The bundled YAML-style reader and writer intentionally support a small,
deterministic subset:

- two-space indentation only, with a maximum nesting depth of 16;
- mappings and sequences, including nested mappings/sequences generated by the
  converter itself;
- `null`, `true`, `false`, finite JSON-style numbers, JSON-quoted strings, and
  simple unquoted scalars;
- JSON-quoted keys and strings in generated output;
- blank lines and full-line comments; an inline `#` remains literal scalar text
  rather than being interpreted as a comment.

It rejects tabs, anchors, aliases, tags, block scalars, flow collections,
duplicate keys, unsafe object keys, unsupported indentation, and values outside
the resource limits. A rejected YAML-looking file remains ordinary text; it
never becomes a partially repaired structured document.

## Guided local workflow

1. Select **Choose file** and choose one direct local regular file in the
   native picker. Network/URL paths, links, folders, and special files are
   refused.
2. The application reads at most 64 KiB to classify the file. Files at or
   below 8 MiB receive complete in-process validation before eligible targets
   appear. A source larger than 8 MiB is classified from its bounded prefix
   only and receives no output route.
3. Choose an available output. The disclosure beside the target says whether
   representation, formatting, byte-order-mark handling, or table shape can
   change.
4. Select **Choose output name and convert**. The native save dialog proposes
   a safe output filename only; it does not reveal or reuse the source folder.
   Existing files are refused instead of overwritten.
5. The app reads the selected source again, verifies it has not changed,
   converts only in memory, validates the generated output, writes a temporary
   sibling file, validates it again, then renames it into the newly chosen
   destination. The source file remains unchanged.

The output limit is 16 MiB. Base64 and hex are available only when their
expanded output remains within that bound. Conversion is cancellable before
the write step; a cancellation does not create an output file.

## Adapter catalog and unavailable formats

The catalog always shows these categories: Documents/PDF, Images, Audio,
Video, Archives, Structured Data/Spreadsheets, Code/Text, and Binary
Encodings. It marks the app-owned text/structured-data/binary encoders as
bundled and available. PDF operations, image/audio/video conversion, archive
packaging, XML transformation, and native workbook formats remain visible but
disabled because this package has no verified bundled offline engine and output
validator for them.

No unavailable card opens a shell, looks on `PATH`, downloads a dependency,
uses a network service, or substitutes an approximate output.

## Bounds, validation, and privacy

- Source selection is restricted to a direct local regular file, with an 8 GiB
  inspection bound, a 64 KiB sniff bound, and an 8 MiB complete-conversion
  bound.
- Structured values are limited to depth 16, 400,000 tracked values, 5,000
  rows, 80 columns, 32,768-character cells/strings, and 160-character keys.
- Each generated output is limited to 16 MiB. Reopened UTF-8, JSON, CSV, TSV,
  YAML-style, Base64, and hex output is validated again before success is
  reported.
- An active source path exists only in main-process memory while the current
  selection is usable. The renderer receives a filename label, never the full
  source or destination path.
- Persistent converter records store bounded result metadata only: filename
  label, byte count, detected kind, target label, outcome, and timestamps.
  They never retain a source path, destination path, source bytes, output
  bytes, or file contents. Legacy inspection records are migrated by retaining
  only safe metadata and dropping their saved source locations.
- The converter has no network client, analytics, telemetry, upload route,
  shell, `PATH` discovery, external process, or arbitrary command input.

The result record store is private application data, not a document history,
backup, export, or synchronization format.

## Failure and recovery

| Situation | Visible result | Recovery |
| --- | --- | --- |
| Native source picker is cancelled | No active source is created. | Choose a local source when ready. |
| Source is a link, network path, URL, folder, special item, or exceeds 8 GiB | The source is refused before a conversion is offered. | Choose a direct local regular file. |
| Source exceeds 8 MiB | Its prefix classification is visible, but no in-process output target is enabled. | Choose a source within the displayed conversion bound. |
| JSON/CSV/TSV/YAML-style validation fails | The source stays text or binary; structured targets are not offered. | Correct the source or choose a supported text/encoding route. |
| A table contains nested values or too many rows/columns | CSV/TSV output is refused before any destination write. | Use a bounded scalar-record table. |
| Output target is cancelled | No conversion starts and no output is written. | Choose a new local output name. |
| Output name already exists | The converter refuses to overwrite it. | Choose a new output name. |
| Source changes between validation and conversion | The conversion stops before output is written. | Re-select and validate the source. |
| Cancellation arrives before the write step | No output is written; a safe cancelled result record is added when record storage is available. | Choose a target again when ready. |
| Result-store persistence is unavailable | The source remains unchanged and the UI names the record-store problem. | Restore private application storage before another conversion. |

## Remaining boundary

This delivery keeps one active source in main-process memory. It does not add a
general multi-file queue, an unlimited/resumable batch engine, a conversion
preview, overwrite support, a file-content export, PDF tools, media tools,
archive tools, XML tools, native workbook tools, or external adapter discovery.
The visible cancelling state is best-effort for the bounded in-process steps:
it can stop before the atomic write, but it is not a claim of a long-running
streaming conversion scheduler or percentage-accurate transfer progress.

## Search and pattern helper

The adapter catalog has local plain-text search by default and an adjacent
ECMAScript pattern helper. It bounds patterns to 128 characters and samples to
512 characters, supports character class/anchor/group/alternation/quantifier
tokens, synchronizes the query and raw pattern, and reports invalid syntax
inline. It searches only the displayed adapter catalog.

The broader application-wide regex-builder, localization, accessibility,
appearance, and complete converter-surface requirements remain separately
incomplete.

## Verification boundary

This is source-level delivery under the active speed-delivery workflow. No
tests, linting, independent review, build, packaging, installed-artifact
interaction, real conversion run, accessibility validation, or capture was
performed or claimed here. The completeness inventory keeps localization,
focused tests, built-artifact interaction, capture, and complete universal
converter evidence pending. Source registration is not evidence of a packaged
or user-observed conversion.
